## description: Always analyze, study, and plan before making any code changes.

# Development Workflow

Before starting any coding task, follow this process strictly:

1. **Understand the Requirement**

   * Carefully analyze the requested feature, bug, or change.
   * Understand the existing project structure and related functionality.

2. **Study the Existing Code**

   * Identify all relevant files, components, APIs, database logic, dependencies, and data flow.
   * Check how the current functionality works before proposing changes.
   * Consider possible side effects and breaking changes.

3. **Create a Detailed Plan**

   * Before writing or modifying any code, provide a clear implementation plan.
   * Explain which files will be changed and why.
   * Describe the proposed data flow, logic, and implementation approach.
   * Identify risks, dependencies, edge cases, and compatibility concerns.

4. **Review Before Coding**

   * Ensure the plan is consistent with the existing architecture.
   * Prefer minimal, safe changes over unnecessary refactoring.
   * Do not assume how existing functionality works—verify it by studying the code.

5. **Start Implementation**

   * Only begin coding after completing the analysis and planning phase.
   * Follow the approved plan.
   * Keep changes focused on the requested task.

6. **Verify the Changes**

   * Check for regressions or unintended side effects.
   * Verify that existing functionality continues to work.
   * Review the final implementation against the original requirement.

**Rule: Never jump directly into coding. Always understand the project, study the relevant code, analyze the impact, and create a proper detailed plan before implementation.**
